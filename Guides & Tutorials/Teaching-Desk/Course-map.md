# Course map

This is the mockup of a RootRecord class. Two lessons are written. The rest are titles and one sentence, so a later pass can fill them without inventing a second outline.

Written pages stay in plain language. A lesson that would turn something on does not get a "try this" step. It gets a "look at this, leave it off" step.

## Track A — a new person at the desk

| # | Lesson | State |
| --- | --- | --- |
| 1 | [The first screen](./For-a-new-person.md) — Root Monitor, the three batteries, what not to press | Written |
| 2 | The poller — the program that keeps writing the log, and why the public URL is that program | Not written |
| 3 | Weather — where today's Hawaii report is, and why a failed NOAA page is a report, not a crash | Not written |
| 4 | Cameras — night frames versus the daylight timelapse that waits until morning | Not written |
| 5 | A scheduled job — open `jobs.py`, find a TEMPLATE, and stop before `enabled` | Not written |
| 6 | Your calls — read the operator list and see which lines are waiting on a person | Not written |

## Track B — an AI editing the same desk

| # | Lesson | State |
| --- | --- | --- |
| 1 | [Before you edit](./For-an-AI.md) — how a file is marked, and what you leave alone | Written |
| 2 | One function — change a line, update its `# info:` note, compile | Not written |
| 3 | One job — copy a TEMPLATE, leave it false, do not restart the poller | Not written |
| 4 | The window — use the handbook instead of describing the UI from memory | Not written |
| 5 | A messy plan — follow the clean-plan guide until there is one document | Not written |

## What this is not

This map is not a work order and not a queue. Filling in lesson 2 is a writing task. It does not migrate a feature, enable a flag, or publish the desk.
