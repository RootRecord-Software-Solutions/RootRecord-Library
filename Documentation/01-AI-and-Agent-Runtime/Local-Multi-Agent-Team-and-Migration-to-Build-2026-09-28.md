## 1. What we are building

Not three disconnected chat sessions. A **local operating system for a small team**:

| Layer | Now (migrate & stabilize) | Later (same shape, more capacity) |
| --- | --- | --- |
| **Roles** | Ava / Carly / Bruce bounds in Library agent packs | Same contracts; stronger models fill the same slots |
| **Shared memory** | Library + agent packs + Work Orders + architecture | Same repos; less path migration, more product |
| **Truth gates** | path landed ≠ runtime verified ≠ legacy retired; Carly seal | Same honesty rules when shipping public/billing claims |
| **Execution** | Bruce on Pacific G3 + desk shell | Same implement/operate lane on larger iron |
| **Mode** | **Migrate & stabilize** | **Build** (features, digests, boards, revenue surfaces) |

GitHub multi-account context (org Library, Pacific, personal agent mirrors) is the **team constitution**. Local small models run that constitution; they do not invent a different org chart each session.

## 2. Pipeline (fixed)

```text
Ava (architect + public voice)
  → Carly (security / honesty seal / WO structure)
    → Bruce (implement & operate)
```

| Agent | Owns | Does not own |
| --- | --- | --- |
| **Ava** | Architecture, external voice, durable strategy docs | Production automation, poller, secrets |
| **Carly** | AppSec, billing wall (proposal-only), honesty/public-copy seal, WO draft rules | jobs.py, deploy, telemetry collection |
| **Bruce** | Runtime, jobs, verification, retirement, surgical implementation | Long-range product narrative, security self-seal |

No self-approval of architecture into production. Draft ≠ deploy. Seal ≠ runtime authorization unless operator accepts and Bruce verifies.

## 3. Small local models are a throughput limit, not a design limit

Constrained NPU / small LLM environments remain valid for the **team system** if:

1. **Thin models + thick context** — packs, WO index, checklists carry structure; the model fills slots  
2. **Specialists over generalists** — role-scoped prompts (seal vs runbook vs architecture)  
3. **Deterministic outer loop** — worklog, FAIL patterns, G3 verification checklist; LLM only where judgment is required  
4. **Fail closed** — Unknown / Waiting / No data preferred over invented LIVE or COMPLETE  

Hardware upgrades later should **multiply speed and depth**, not force a rewrite of roles, WOs, or truth gates.

---

## 4. Why migration-first

Pay the tax once:

- One production poller host (G3 Pacific)  
- One path language (Pacific domains + Database for generated bytes)  
- One secret-hygiene story (local only; never archive/mirror tokens)  
- One agent refusal pattern for false LIVE  

Unfinished dual paths (G2 skills poller, second getUpdates owner, optimistic docs) become permanent drag on every future build.

**Close cutover before build-mode sprawl:** merge honesty seals to main, run G3 runtime verification on the desk, retire verified legacy **executables** (keep `SKILL.md`), then expand product.

- Communications notify under sealed policy  
- Product recovery from G1/G0 by **diff**, never bulk-merge  

---

## 6. Business capacity and hardware

Upgrade trigger is **not** “models feel smarter.” It is when the business model funds reliable capacity for:

- Stronger local or hybrid inference without thrashing the desk NPU  
- Parallel agent sessions without starving single-flight discipline  
- Optional always-on verify loops so operations are not blocked on a single laptop session  

Until then: close migration, keep honesty gates, prefer **one external surface that can earn** over migration theater.

Standing phrasing: plan for **when** the business supports upgrade — not speculative revenue metrics in docs.

---

## 7. Standing rules (all agents)

1. **path landed ≠ runtime verified ≠ legacy retired**  
2. Measured or explicitly Unknown — no invented metrics or residual paths  
3. No secrets in git, chat, or WO text  
4. Document-only until a WO is accepted for execution  
5. Same team constitution on small or large hardware  
6. Do not skip residual verification to start build-mode features
